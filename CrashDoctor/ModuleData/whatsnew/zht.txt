更新內容

• 新增防護：戰鬥結算時被移除的隊伍沒有所屬家族而當機。遊戲對離開世界的隊伍做的最後一件事，是把它從家族的作戰隊伍名冊中註銷——卻在呼叫家族時從不檢查家族是否存在。隊伍失去家族的情形有兩種：某個模組銷毀或解散了一支已經被移除的隊伍，或手動清空了它的家族。新的「隊伍移除崩潰防護（隊伍無所屬家族）」會略過這個不可能完成的呼叫，並自行把隊伍註銷，移除流程正常收尾，戰役繼續。

• 新增防護：因一面沒有效果的旗幟導致佈陣畫面當機。遊戲在產生指揮官提示時會讀取該部隊旗幟的效果，卻不檢查它是否存在——而資料中指向了任何已安裝模組都未定義的效果的旗幟，正是沒有效果，於是戰鬥根本無法開始。新的「佈陣畫面崩潰防護（旗幟資料損壞）」會顯示不含旗幟部分的提示，並把該旗幟的 id 寫入記錄檔。

• 新增防護：戰鬥結算時某一方已失去主導隊伍而當機。遊戲在關閉戰鬥時會連續在半打地方讀取這支隊伍，卻從不檢查它是否還在。新的「戰鬥結算崩潰防護（無主導隊伍的一方）」採用遊戲自己的規則：由該方仍然存在的第一支隊伍接任——一次覆蓋所有這些位置。

• 新增防護：因駐軍失去其據點，戰役地圖每隔幾秒就當機。隊伍治療的計算會直接從隊伍上讀取據點，因此失去歸屬的駐軍會讓整個戰役結算當機——每次讀檔幾秒後重現。新的「隊伍治療崩潰防護（駐軍無據點）」只略過這一支隊伍在本次結算中的治療；失去歸屬的駐軍會在進入戰役時被清理。

• 新增防護：存檔在每次讀取後約一秒就當機。遊戲每一刻都會詢問進行中的戰鬥雙方是否處於戰爭狀態，卻不檢查主導隊伍是否仍屬於某個勢力——在戰鬥中被消滅的隊伍正好是這個樣子，而這場損壞的戰鬥保存在存檔裡。新的「戰鬥崩潰防護（無勢力的主導隊伍）」會結束該戰鬥而不是當機。

• 家族實力的讀檔防護現在在 Bannerlord 1.2 上也有效。該引擎方法在 1.2 上名稱不同，因此防護此前從未安裝——儘管當機完全一樣。

• 新增辨識：著色器已編譯卻從未儲存。引擎會在記錄檔裡寫下 "Could not write shader cache file" 然後繼續執行，看起來像是建構成功、下次啟動又從頭再來。這既不是快取損壞也不是驅動問題：ProgramData 中的著色器資料夾缺少或無法寫入。

修正

• 移除了兩條錯誤的「已避免崩潰」提示。其中一條會在 Bannerlord 1.2 上針對該版本根本不會發生的當機彈出；另一條把沒有船隻資料的勢力判定為問題，即使遊戲本可以正常處理。兩者都會讓玩家去移除一個毫無問題的模組。

• 「已避免」頁的計數不再因一場卡住的戰鬥而虛增。此前防護會在每一影格觸發，一次事件就能把計數推到數千。現在這樣的戰鬥只計一次。

• 一次當機，一個結論。損壞戰鬥引起的當機可能同時顯示兩張建議相反的卡片。現在只顯示符合實際情況的那一張。

• 「微調」頁在系統管理員權限相關文字中也使用繁體中文：分頁檔、TDR 延遲與 Game DVR 的提示及套用／還原失敗說明此前顯示為簡體。

• 「存檔」頁不再因 Game Saves 中的某個無法讀取的子資料夾而變空——這樣的資料夾會被略過。
