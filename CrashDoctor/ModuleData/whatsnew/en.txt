Thanks for using Crash Doctor!

WHAT'S NEW

• The mod now knows which build of another mod your game needs. It ships a compatibility reference: which build of each mod was made for which Bannerlord branch, what to install instead of a mismatched one, and the page to get it from. No network — the data is read from inside the mod.

• The Mods tab marks mods whose own code was checked against your exact game build with a green "checked" tick, and mods that were not built for it in red — with the version you need and a button to its file page. "OK" used to mean both "checked, fine" and "we have never heard of this mod"; those are two different answers now. It also covers disabled mods, because warning you before you switch one on is the only way to catch this in time.

• The crash card tells you what is wrong with your setup: the enabled mods that are not built for your game version, with the versions you want. This is not a claim that any of them caused the crash — naming a culprit needs the top stack frame — but it answers "is this setup even supposed to work?".

• report.txt has been rebuilt. The setup verdict is in the first ten lines, ahead of anything long. Added: the game and mod versions, the managed exception with its throw site and stack, and the list of active guards (a guard that fires removes a frame from the stack, and without that list the trace reads wrong). The module list is no longer cut off at twelve.

• A new "Our other mods" window on the Settings tab. When the game runs from Steam the Workshop button leads — one click to subscribe instead of unpacking an archive by hand. Nothing is installed from the window; everything opens in your own browser.

FIXES

• New guard: a day-change crash when a lord has nowhere to raise his party. Once a day the game gives a lord a place to gather his men, and sometimes it meets one with nowhere at all to start from — no town, no castle, not even a village of his own people. It gives up, taking the day with it. That is a hole in the game itself, not a mod bug. The guard musters him somewhere sensible instead; the lord and his culture go into the log, which shows where these homeless lords come from.

• Two new guards for campaigns that refuse to start at all. A faction file naming a character no installed mod defines, and an equipment file written for an older Bannerlord — either one kills the whole load, and no mod appears anywhere in the crash. The guards skip only the broken entry, so the campaign starts; and the Mods tab now finds both in the files beforehand and names the mod to update.

• The System Tune-Up tab no longer freezes the interface. Disk, registry and process checks moved to a background thread, and the screen shows which check is running and how long it has been going. One walk of a multi-gigabyte temp folder used to freeze the window for seconds and made the mod look hung.

• The Prevented tab appears only when the journal has something in it: on a healthy setup no guard ever fires, and the tab was a button with nothing behind it.

• Esc closes the window that is open, not the whole tool. On a destructive confirmation, Esc means cancel.

• Two guards used to cry wolf. One announced a prevented crash every time an AI clan simply JOINED a kingdom; the other did it whenever the game removed a troop that was no longer in the roster — without ever checking who asked, so a mod that catches its own error looked like a rescue. No harm was done to your campaign, but the prevented-crash count was wrong. Both now claim a save only when the game itself would really have died.
