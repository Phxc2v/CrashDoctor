Thanks for using Crash Doctor!

WHAT'S NEW

• New "is this mod working at all" check: a missing library (ButterLib, MCM, UIExtenderEx, Harmony, BLSE) or a half-extracted archive now flags the mod on the Mods tab, naming the exact missing file — before it turns into anything.

• New "Prevented" tab — a running journal of the crashes that were stopped: what exactly, how many times, which mod, and on which game data. Press Ctrl+Alt+D for the same list in a campaign.

• Prevented-crash messages now name the object the game tripped over: the troop and its missing culture, the party, hero, clan or settlement.

• They also name the mod whose code threw — but only when that can be determined honestly. If the game's own code threw, no mod is named; a wrong name gets an innocent mod uninstalled.

• Donations reworked: one page in two forms — a normal web page that takes a card without Telegram, and the same page inside Telegram — picked for your language, with the address shown in full and a copy button.

GUARDS AGAINST CRASHES

• A battle handing out loot with a settlement among the winners — a village repelling a raid, a town repelling an assault. Typical symptom: the save loads fine and the game crashes the moment you start moving.

• Sharing out prisoners right after a battle, when the game removes a troop that is no longer in the roster. That one transfer is skipped and the battle finishes.

• A child being born to a parent that has no body-shape data — a character some mod created in code. The newborn gets an average build and the day passes.

• A town raising a rebellion when its culture has no rebel-hero templates. That town does not rebel and is rolled for again the next day.

• The daily error about a rebel clan the game never registered — usually a clan left behind by a mod added or removed mid-save. It repeated every single day, once per clan.

• Party wages on the day change; the wage of the problem party counts as zero for that day.

• Auto-upgrading an AI party's troops — a divide-by-zero in the game itself when a higher-tier troop is paid the same wage.

• A town creating a smithing order; the order is skipped and the slot is filled the next day.

• A battle ending with a hero killed in it — the pass is restarted, so the result is applied in full.

• An AI clan leaving a kingdom it no longer belonged to, usually after a mod moved that clan's leader.

FIXES

• The "What's new" window no longer appears over the first-launch brightness setup, and no longer beats the menu to the screen. The check that was supposed to prevent this was reading a property the game does not have, so it never once ran.

• Mod settings and markers are no longer lost when Windows has redirected Documents into OneDrive. They now live in a folder that is always readable at startup, and what you already had is moved across once.

• A crash report no longer calls the game's own code a third-party mod when that code happens to be patched.

• The Tune-Up tab now speaks Traditional Chinese — every status and result line, not just the cards.

• "Don't show news again" checkbox on this window: tick it and close, and it will not return on this version or any future one.

• Crashes in the game's native finalizer (AccessViolation) are diagnosed correctly, including the case around The Old Realms' "Build Shader Cache" button.

• Repair for a broken Windows TEMP path: if TMP/TEMP point at a drive that is gone, the Tune-Up tab restores the standard path in one click.

• The crash report now ships with crashdoctor_at_crash.log, which shows the exact troop, party or settlement the game broke on.
